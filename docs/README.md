# 文件索引與閱讀規則

- 基線：v0.2｜2026-11-21
- 專案階段：設計與灰盒前期（M0）；尚無可玩版本
- 公開工作名：Twinfront Command（中文暫譯《雙線指揮》）
- 文件語言：以繁體中文（台灣用語）為準；英文摘要與翻譯歡迎貢獻

這份索引說明「哪份文件回答什麼問題」，以及發生衝突時以哪一份為準。目標是避免同一件事被抄成三份，最後三份都不一致。

## 2. 單一來源規則

- **需求與產品決策**只在 `product-brief.md`。其他文件用 `REQ-xx`、`DEC-xx` 引用，不重抄表格。
- **規則與數值**只在 `game-design.md`。內容 JSON 上線後，數值以內容資料為準，文件只做摘要與連結。
- **技術邊界與契約**只在 `architecture.md` 與 `adr/`。ADR 一旦被取代，保留舊檔並標記 `Superseded by ADR-xxxx`。
- **里程碑與範圍**只在 `roadmap.md`。團隊用的 HTML 或簡報若存在，必須標明「快照」與日期，不手改。
- **執行紀錄**在 GitHub Issues 與 Pull Requests。這裡不放工作日誌、逐日進度或流水帳。
- **不宜公開的內部背景**（實際工時、內部基礎設施規格、私人 repo 盤點、agent 分工、預算、帳號狀態、試玩者個資）留在專案內部紀錄，不進這個 repo。

## 3. 狀態標籤

文件中的主張一律標明成熟度，避免把候選值讀成承諾：

| 標籤 | 意思 |
|---|---|
| **【已決】** | 已拍板；要改需開新決策或 ADR |
| **【暫定】** | 目前預設，但可在指定決策點更換 |
| **【假設】** | 待驗證的主張；不是承諾 |
| **【待決】** | 尚未拍板；有負責人與決策點 |
| **【不做】** | 明確的非目標；不是「以後再說」 |

沒有標籤的句子通常是背景說明或已被引用的事實；若會影響範圍、成本或對外承諾，就應該有標籤。

## 5. 名詞對照

| 中文 | English | 說明 |
|---|---|---|
| 總部 | HQ | 被攻破即終局；每方一座 |
| 前哨 | outpost | 每方 2 座、每路 1 座，全場 4 座；首次摧毀敵方前哨給一次補給 |
| 路線／戰線 | lane | 雙路地圖的進攻路線；MVP 暫定不互通 |
| 補給 | supply | 唯一資源；用於生產、研究、砲塔 |
| 生產佇列 | production queue | 待生產訂單；上限指訂單數，不是場上單位數 |
| 排產 | production scheduling | 選擇兵種、路線與下單時機 |
| 自動交戰 | auto-combat | 下令後單位自動移動與交戰，不是離線掛機 |
| 即時可暫停 | real-time with pause | 目前的工作假設，待 W2 對照 |
| 同步回合 | synchronous turns | W2 要對照的另一種節奏 |
| 灰盒 | greybox | 無正式美術、只驗證規則與操作的原型 |
| 垂直切片 | vertical slice | 從開局到結算可完整走通的最小版本 |

## 6. 修改這份索引

新增文件時，先回答「它是否會成為某類資訊的唯一來源」。若只是簡報、快照或重複摘要，不要新增文件；放到既有文件或標明為快照。文件拆分或合併時，更新本索引與 `ways-of-working.md` 的責任表。
