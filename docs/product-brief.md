# Twinfront Command — 產品簡報（Product Brief）

- 版本：v0.2｜2026-11-21｜已納入基線審閱；**尚未凍結**
- 文件角色：原始需求、證據狀態與產品決策的單一來源。不是設計規格、不是排程、也不是工作紀錄。
- 公開工作名：Twinfront Command（中文暫譯《雙線指揮》）。舊企劃名《前線指揮部》不再作為公開名稱；正式名稱待 DEC-01。
- 來源 S1：2026-11-20 09:58 CST 的開案訊息。以下是整理摘要，不是逐字訪談紀錄。
- 證據等級：目前只有發起人輸入（S1）。尚無獨立玩家訪談、試玩、效能實測或平台驗證。

## 1. 一句話定位

一款 8–12 分鐘、雙路線、下令後自動交戰的 1v1 策略遊戲：玩家在補兵、研究與防守之間取捨，目標是在對手攻破自己的總部前，先攻破對方總部。

這是**產品方向**，不是已驗證的市場結論。目標玩家、節奏與「放置」的界線仍待 DEC-01／DEC-02 確認。

> 名詞說明：原始訊息用「放置型」，指的是部署單位、下令後自動執行；本文件在公開描述改用「部署＋自動交戰」，避免被讀成離線掛機（idle game）。

## 2. 這個產品是什麼／不是什麼

**是：**

- 一場可以在 iPad 或普通筆電上完成的短局；不需要高階顯卡。
- 以部署、路線分配、生產順序與研究時機為主要決策。
- 單位下場後自動執行；玩家的操作負擔低於傳統 RTS。
- 架空陣營與架空數值；可讀性優先於歷史還原。

**不是：**

- 不是離線掛機或點擊累積型遊戲。早期文件中的「放置」指**部署**，不是 idle。
- 不是基地建設、歷史模擬或真實裝備百科。
- MVP 不是真人 PvP、多人同步、跨平台帳號或排行榜。
- MVP 不是 Roblox 產品；Roblox 是 Web MVP 後的研究軌。

## 7. 產品邊界

- **MVP 的承諾**：一場可從開局走到結算的單機對局；觸控可完成；規則可重播；沒有伺服器也能玩。
- **MVP 的候選內容**：雙路、每方 2 座前哨（全場 4 座）、4 種地面兵、固定砲塔、2 條研究線、AI、教學、結算。實際 P0 以 W2 凍結為準。
- **明確不在 MVP**：真人 PvP、多人同步、離線金幣、跨平台帳號、排行榜、雲端存檔、海空單位、碉堡、關卡編輯器、Mod 支援、3D 渲染、Roblox 公開上架。

- 調整**原始需求**：保留原文摘要與來源，附上變更日期、原因與確認人；不要直接改寫歷史。
- 調整**設計方案**：更新 `game-design.md` 或提案，不改寫 REQ；若影響範圍或承諾，開 DEC 或 ADR。
- 調整**產品決策**：在 DEC 表中更新狀態與日期；已決項目要改，開新 DEC 取代，不覆蓋舊紀錄。
- 新增需求：先問「這是原始需求、衍生需求，還是設計選擇？」只有前兩者進本文件；設計選擇進 `game-design.md`。
- 對外承諾（日期、平台、效能、授權）必須有狀態標籤；【假設】與【暫定】不得寫成對外保證。
