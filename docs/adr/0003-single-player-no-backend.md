# ADR-0003：單機、無後端 MVP

- 狀態：Accepted（暫定）
- 日期：2026-11-21
- 決策者：維護者／產品
- 相關：REQ-06、DR-03、DR-05、DEC-04、DEC-05

## 背景

- 目標是 8–12 分鐘的單機 1v1 對 AI；不需要真人配對。
- 團隊小、維運預算低；不想在 MVP 階段處理帳號、資料庫、伺服器權威與作弊。
- 玩家隱私與公開 repo 的信任：不要為了 MVP 收集不必要的資料。
- 未來可能有 PvP、排行榜或雲端存檔，但那是另一個產品階段。

## 決策

MVP 是**單機、靜態、無後端**：

- 1v1 對 AI；沒有真人 PvP、配對、聊天或排行榜。
- 沒有帳號、Email、個資、第三方分析、廣告或追蹤。
- 只在本機保存設定、教學狀態與最近結算；不存中途戰局。
- 部署為靜態檔案；沒有 API、資料庫或伺服器邏輯。
- 若未來加入 PvP／雲端，需新的 ADR 與伺服器權威模型，不是 MVP 的漸進功能。

## 後果

**正面：**

- 隱私負擔低；不需要隱私政策以外的複雜合規。
- 維運成本低；靜態 hosting 即可。
- 不會有伺服器延遲、作弊或配對問題。
- 可以完全離線遊玩（載入後）。

**負面／成本：**

- 沒有雲端存檔、跨裝置同步、排行榜或社交功能。
- 玩家清除瀏覽器資料就會失去設定；文件要說清楚。
- 沒有真人 PvP，長期留存可能受限。
- 若之後要做 PvP，大部分前端與模擬可重用，但伺服器、驗證、配對與安全要重做。

**影響：**

- 遊戲設計不要依賴伺服器時間、遠端設定或線上活動。
- 平衡與內容更新靠版本發布，不是遠端 hotfix。
- 試玩與 bug 回報要靠玩家提供 build／種子，不能遠端讀取。

## 替代方案

| 方案 | 為什麼不選 |
|---|---|
| PvP 優先 | 需要伺服器權威、配對、作弊防制與維運；MVP 風險太大 |
| 雲端存檔＋帳號 | 增加隱私、認證與維運成本；短局不需要 |
| 排行榜 | 需要後端、反作弊與賽季設計；不是核心樂趣 |
| 只做本機但加分析 | 會破壞「無追蹤」承諾；MVP 不需要 |

## 證據

- 這是產品與架構的暫定決策；尚未有玩家留存數據。
- 若 M3 試玩顯示「沒有 PvP 就不想再玩」，再開 DEC-04 或新 ADR 評估。

## 重評條件

- 多數試玩者明確表示沒有 PvP／排行榜就不會再玩，且這是核心阻礙。
- 單機 AI 無法提供足夠的挑戰或重玩價值。
- 平台或商業模式要求帳號／雲端功能。
- 維護者決定把專案推進到商業化階段。
