# ADR-0004：對局節奏——即時可暫停（提議中）

- 狀態：**Proposed**（不是已決；W2 由 DEC-02 拍板）
- 日期：2026-11-21
- 決策者：產品／設計／維護者
- 相關：REQ-03、H-01、DEC-02、DQ-04、[playtesting §6.2](../playtesting.md#62-dec-02-的決策規則)

## 背景

- 原始構想允許「雙方同時進行」或「回合制」，沒有排除任何一種。
- 目前計畫以即時可暫停作為預設，因為較接近原構想，也讓 iPad 玩家可以暫停後下令。
- 但觸控可能讓即時操作太忙；同步回合可能更清楚，卻可能失去緊張感。
- 兩種節奏若各做一套完整遊戲，成本會失控。

## 提議的決策

在 W2 前，以**即時可暫停**作為預設實作，但不算已決：

- 玩家可隨時暫停；暫停時不推進遊戲時間。
- 提供慢速或低壓模式，降低操作負擔。
- 用同一個灰盒、同一張地圖、同一個種子，對照「即時可暫停」與「每 5 秒規劃＋5 秒同時執行」的同步回合。
- 模擬核心不綁節奏；節奏由 app 層的 scheduler 決定何時推進 tick。
- W2 依 [`playtesting.md`](../playtesting.md) 的決策規則選擇；結果寫回本 ADR 或開新 ADR。

## 後果

**若選即時：**

- 較接近原始構想與「自動交戰」的張力。
- 需要處理觸控誤觸、暫停可發現性、背景分頁與即時回饋。
- AI 與特效的節奏要更清楚。

**若選同步回合：**

- 操作負擔較低，觸控與教學可能更清楚。
- 需要重做 UI 的規劃／執行階段、計時器與回合回饋。
- 可能失去「同時進行」的緊張感與部分原始構想。

**共同成本：**

- 兩種模式都要測試，不能在 W2 前只做一種就宣布勝利。
- 若兩種都失敗，不能二選一；要先修 UI、教學與經濟，再測一輪。

## 替代方案

| 方案 | 為什麼暫不選 |
|---|---|
| 直接承諾即時 | 沒有觸控證據；會讓 W2 變成橡皮圖章 |
| 直接承諾同步回合 | 偏離原始構想；也還沒有證據 |
| 兩套完整遊戲並行 | 成本過高；小團隊會兩邊都做不好 |
| 只做即時，不做 A/B | 無法回答 DEC-02；風險留到後面 |

## 證據

- 尚未試玩。W2 的 5–8 人交叉試玩是決策依據。
- 決策規則：完成率 ≥80%、取捨理解 ≥70%、中位局長 8–12 分鐘、無致命觸控錯誤；偏好只作輔助。

## 重評條件

- W2 試玩結果顯示另一種節奏明顯較好。
- 觸控或可讀性問題無法在即時模式下解決。
- 同步回合讓局長或教學明顯改善，且不犧牲核心取捨。
- 平台或裝置限制使即時模式不可行。
