# ADR-0001：轉向情報欺敵策略玩法，並暫定 Three.js 雙尺度渲染

- 專案：Frontline Signal（`frontline-signal`）
- 狀態：提案（Proposed）｜2026-11-23
- 決策者：發起人（產品）；工程與 QA 於 CP2 依真機數據確認引擎部分
- 關聯需求：REQ-01, REQ-03, REQ-04, REQ-06, REQ-09
- 關聯決策：DEC-02, DEC-03

## 背景

初版企劃將遊戲定調為「固定雙路、自動推進、塔防式經濟」的放置型策略遊戲。發起人於 2026-11-22 提出新方向：參考 *R.U.S.E.* 這類情報欺敵 RTS 的玩法類型，強化可縮放戰場、情報不對稱與欺敵決策（只借鏡玩法類型，不沿用名稱、介面、美術或內容），並同步評估適合一般電腦與 M1 iPad 瀏覽器的畫面引擎；2026-11-23 正式定名為 **Frontline Signal**。

## 決策

1. **玩法方向調整**：
   - 地圖由「固定雙路軌道」改為「5–7 個連通區域＋橫向換側通道＋補給節點」。
   - 引入獨立情報層：區分己方、已確認敵軍、未確認接觸與最後已知位置；首版提供「掃描」與「假接觸（誘餌）」兩個情報行動。
   - 模擬架構強制分離 `WorldState`（真實狀態）、`PlayerView`（單方可見情報）與 `RenderScene`（畫面呈現）；AI 只能讀取自身 `PlayerView`，不得作弊讀取全域真相。
2. **畫面引擎暫定**：
   - 暫定採用 **Three.js（優先 WebGL 2 路徑）** 實作「近景低模 3D 單位＋遠景 2D 戰略棋子」的雙尺度縮放。
   - CP1 灰盒不綁引擎，以最輕量的 2D（SVG 或 Canvas 2D）呈現 `PlayerView`，只驗證玩法。
   - 第 2 週（CP2）保留 **PixiJS 純 2D** 同快照對照選項；若真機實測顯示 3D 近景未帶來決策價值或效能不達標，則切回純 2D。
   - 暫不採用 Godot 4 Web 匯出（Safari WebGL 2 相容性風險）或 Unity（重型工具鏈與首載成本），亦不為 Roblox 設計跨引擎共用 renderer。

## 取代與保留

- **取代**：固定雙路純推線、單純以出兵克制為唯一核心。
- **保留**：二戰及戰後題材、HQ 攻破終局、擊毀統計、資源與研發循環、低微操自動交戰、碉堡獨立追蹤、M1 iPad／一般電腦效能目標、Roblox 非 MVP。

## 後果與重新評估條件

- **正面**：玩法辨識度大幅提升；`PlayerView` 分離讓未來若導入 PvP 時具備伺服器防作弊基礎。
- **代價**：需增加區域連通、視野／情報狀態機與雙尺度渲染切換的工程複雜度。
- **重新評估觸發條件**：
  1. 第 1 週灰盒試玩（CP1）中，多數玩家仍只記得不斷造兵、無法說出情報如何改變部署。
  2. 第 2 週（CP2）M1 iPad Safari 真機測試在 60 單位正常場景下無法達成幀間隔 p95 ≤ 33.3 ms，或快速縮放出現明顯掉幀／誤觸。
