# ADR-0001：Web 優先，TypeScript＋Vite＋Canvas 2D

- 狀態：Accepted（暫定；可在原型比較後重新評估）
- 日期：2026-11-21
- 決策者：維護者／工程
- 相關：REQ-06、REQ-07、H-02、H-05、DEC-04、TQ-01

## 背景

- 原始構想要求普通電腦與 iPad 可玩，不需要高階顯卡。
- Roblox 是後續選項，不要求在 MVP 上架。
- 團隊規模小，需要快速迭代、可重播的測試與低成本部署。
- 曾有一個內部戰鬥原型；只借鑑部署、輸入與效能量測經驗，不直接重用程式，除非授權與耦合都確認。

## 決策

MVP 做成**靜態 Web 應用**：

- TypeScript＋Vite。
- 渲染先用 Canvas 2D 精靈與俯視格線。
- 3D／Three.js 只在原型比較證明有明確收益時才導入。
- 部署為靜態檔案；沒有伺服器、資料庫或帳號。
- Roblox 保持研究軌，不在 MVP 承諾共用程式碼或素材。

## 後果

**正面：**

- 迭代快、部署便宜、可在桌機與 iPad Safari 直接測試。
- 與既有網頁經驗和量測方式接近。
- 不需要維護第二套客戶端或伺服器。

**負面／成本：**

- Safari 與 iPad 的觸控、記憶體、背景分頁限制要真機處理。
- Canvas 2D 在大量單位與特效下可能成為瓶頸；需要批次繪製與降級。
- 沒有原生商店曝光；沒有 Roblox 的內建受眾。
- 若之後做 Roblox，規則與內容可參考，但 UI、渲染與部分程式要重寫。

**影響：**

- 內容與規則要與渲染解耦，方便未來移植。
- 效能量測以瀏覽器與真機為準，不以 CI 的 GPU 數據代替。

## 替代方案

| 方案 | 為什麼不選 |
|---|---|
| Roblox 優先 | 平台規則、內容審核與第二客戶端成本高；MVP 風險太大 |
| Unity／Godot | 對這個規模過重；Web 匯出與觸控仍需額外驗證 |
| 3D Web（Three.js）優先 | 美術與效能成本高；先用 2D 驗證規則與節奏 |
| 直接重用舊原型程式 | 授權與耦合未確認；先借經驗，不借程式 |

## 證據

- 尚未有本專案的效能實測；以既有網頁遊戲在 M1 Pro 與 M1 iPad 的體驗作參考。
- 這是 provisional decision；M0 的灰盒與基準會驗證。

## 重評條件

- Canvas 2D 在 60 單位正常場景無法達到 p95 ≤33.3 ms，且降級無效。
- 美術方向必須用 3D 才能達到可讀性或有明確市場收益。
- 觸控或 Safari 限制使 Web 版本不可行。
- Roblox 受眾與成本明顯優於 Web，且 DEC-04 決定轉向。
