# Roblox 發布研究（Research Note）

- 狀態：研究筆記，**不是承諾、不是路線圖**
- 事實查核日：2026-11-21
- 相關：REQ-07、H-05、DEC-04
- 用途：在 Web MVP 之後判斷是否值得做 Roblox 切片；平台規則會變，決策前必須重新查證。

> 這份筆記刻意與 `roadmap.md` 分開。平台費用、年齡門檻、受眾評估與審核流程變動快；把它們寫進承諾型路線圖，會讓計畫看起來比實際更確定。

## 1. 為什麼考慮 Roblox

- 內建受眾與社交分發，可能比一個新 Web 遊戲更容易被看到。
- iPad／手機客戶端現成；不需要自己處理裝置商店。
- 對「短局、自動交戰、可讀性高」的遊戲類型，Roblox 上有相近受眾。
- 若 Web 版證明規則有趣，Roblox 切片可以驗證另一個平台，而不是從零猜測。

## 2. 為什麼不現在做

- 第二套客戶端：Luau 重寫規則、Studio 重做 UI／場景、另一套效能與觸控驗證。
- 平台內容審核：戰爭題材、圖標、歷史符號、縮圖與音訊都要審；可能被迫改設計。
- 維護成本：兩個平台、兩套 bug、兩套內容更新；小團隊容易兩邊都做不好。
- 平台規則變動：年齡、費用、受眾門檻與發布流程不是我們能控制的。
- 受眾不確定：Roblox 玩家是否喜歡 8–12 分鐘、非交易的雙路策略，尚未驗證。

## 3. 技術切片（若立案）

不做完整移植，先做一個可結算的私有切片：

| 項目 | 切片範圍 |
|---|---|
| 地圖 | 一條路 |
| 單位 | 兩種（例如步兵、坦克） |
| 建築 | 1 座 HQ；可選 1 座前哨 |
| 規則 | 經濟、生產、傷害、終局；與 Web 版同一組概念 |
| 權威 | 伺服器決定傷害、資源與結果；客戶端只呈現與送指令 |
| UI | Studio 重做；觸控完整；不依賴鍵鼠 |
| 驗證 | 用 fixtures 比對事件結果；Roblox 客戶端測 iPad，不用 Safari |
| 效能 | MicroProfiler 分辨腳本、物理、渲染；正常場景目標 30 FPS |
| 素材 | 可移植的原創美術；重新匯入前確認授權與審核 |

- 切片成功不等於可上架；還要過內容、受眾、成本與維護決策。
- 不承諾與 Web 版共用 TypeScript、UI 或渲染程式；共享的是規則、數值、素材來源與測試向量。

## 4. 發布與受眾（2026-11-21 查核）

以下是當時的平台資訊，**不是保證**；每次決策前以 Creator Hub／Dashboard 重查。

### 4.1 16+／Trusted Friends

- 帳號狀態良好，且至少 2 天。
- 完成年齡檢查。
- 回答年齡限制問題。
- 若涉及限制內容，不假設可用簡化流程。
- 確認地區、內容問卷、素材審核與可及設定。

### 4.2 擴至未滿 16 歲

較高門檻，可能包含：

- 成年創作者 ID 驗證。
- 未成年依規年齡估計。
- 2FA。
- 完整內容問卷與符合分級。
- 費用，或連續兩個月 Plus／Premium。
- 平台評估。

> 原始筆記提到官方 Help 列出的 Robux 選項與受眾門檻；這些數字變動快，不在這裡當成承諾。決策前直接查 Creator Hub 的當前說明，並記錄查核日期。

### 4.3 內容審核

- 假定不保證任何年齡級別。
- 先審查：暴力呈現、圖標／徽章、歷史標誌、縮圖、音訊、素材權利。
- 首版 Roblox 不設自由文字或自製聊天；不把真實歷史素材直接搬上架。
- 若平台要求修改，先暫停該內容，再依流程處理；不要繞過審核。

## 5. 流程

```
私有 Studio 測試
  → 內部小測
  → 內容與團隊檢查
  → 發布給合格受眾
  → 視需要申請擴大受眾
```

- 先建立團隊擁有的 experience；指定所有者、審核責任，限制編輯與發布權限。
- 先在 Studio 發布私有測試；在 go/no-go 前避免付費選項。
- 每一步都要有停損：裝置、內容、成本、人力任一不合格就停。

## 6. Go／No-Go 條件

只有在以下都成立時，才建議立案：

- Web MVP 已驗收，核心樂趣已被 5–8 人驗證。
- Roblox 切片能在合理時間內完成，且不影響 Web 版維護。
- 內容審核不會迫使核心設計妥協（例如必須移除整個陣營或符號系統）。
- 預期受眾與維護成本相比值得；不是「因為 Roblox 很紅」。
- 有人明確負責發布、審核、客服與後續維護。
- 成本上限與停止條件已寫下來。

**No-Go 訊號：**

- 第二客戶端每週維護時間超過可接受範圍。
- 平台要求與內容政策衝突，且無法用架空設計解決。
- 切片完成後，受眾測試顯示留存或理解明顯低於 Web 版。
- 團隊沒有餘力同時維護兩個平台。

## 7. 對 Web 版的影響

- Web 版的規則與內容要可移植：ID 穩定、數值在 JSON、事件與 replay 可對照。
- 不要為了 Roblox 提前做 3D 或平台特定 UI；那會拖慢 MVP。
- 素材授權要可轉移；不要用只允許單一平台的素材。
- Web 版仍是主產品；Roblox 是選項，不是備份計畫。
