# 畫面、動畫與音效方向（Art, Motion & Audio Direction）

- 版本：v0.2｜2026-11-23｜狀態：寫實方向提案（第一輪手繪風格探索稿已否決），CP2 以目標畫面實機驗證後定案（DEC-07）
- 對應：REQ-10、REQ-11、H-06；效能門檻見 `docs/agent-plan.md` 第 04 節
- 原則：**好看要建立在跑得動上**。所有視覺決定都要能在 M1 iPad Safari、正常場景 60 單位、幀間隔 p95 ≤ 33.3 ms 下成立。

## 1. 展示即成品（Fidelity Rule）

對外看到的畫面，必須是玩家實際玩到的畫面。圖像分三級，只有第三級能對外使用：

| 等級 | 是什麼 | 怎麼產生 | 可以用在哪 |
|---|---|---|---|
| 探索稿 | 風格、色彩、氛圍的探索 | 手繪、AI 生成皆可 | 只供內部討論；**不放 README、商店頁、社群** |
| 目標畫面（Target Frame） | 某個場景「成品應該長這樣」的定稿 | 探索稿收斂後，附上**可重現性說明**（用了哪些幾何、材質、光照、特效，各自的效能成本） | 內部開發規格；**實機重現前不公開**。本文件只以文字描述目標畫面的規格 |
| 展示圖 | 對外宣傳、商店頁、README 截圖 | **只能**是遊戲建置在實機上的擷取；記錄 commit、裝置、畫質設定；不得後製修圖（裁切與縮放除外） | 任何地方 |

驗收方式：每張目標畫面都要在對應 checkpoint 以引擎實機重現，與目標畫面並排比對，並同時達到效能門檻。**重現不了的目標畫面要修改目標，不是修改截圖。**

## 2. 視覺支柱

1. **寫實，不卡通**：沒有描邊、沒有誇張比例、沒有糖果色；材質照真實的粗糙度與金屬度，漆面不反光，下緣有塵土。
2. **作戰室桌面是真的桌面**（遠景）：上漆木桌、印刷等高線地圖、木質與琺瑯棋子、鉛筆、尺、電報紙，一盞暖色檯燈的光池。
3. **地圖就是地形**（中景）：遠景的紙圖與近景的地面是同一個網格與材質；拉近時高度長回、紙色淡出成田地與道路、樹與房屋從紙面長出、光線從檯燈轉成陽光。
4. **近景照真實公尺**：載具採真實二戰車型並依真實尺寸建模（DEC-06），步兵與火砲同樣照實際比例。
5. **情報是看得見的**：推測的東西用「筆」畫（油性筆圈、問號、鉛筆虛線），確認的東西用「實物」表示（棋子、3D 單位）；同一語意在三個尺度用同一個形狀與顏色。
6. **可讀性優先於細節**：敵我以形狀（我方矩形、敵方菱形）＋顏色（藍／橙）＋位置三重區分，色盲與灰階下仍可讀。

## 3. 渲染方向與效能預算

> 本節數字是 three.js 原型在軟體繪圖環境下量到的**提案值，尚未在 M1 iPad 實機驗證**。CP2 以實機量測（正常 60 可動單位、實際 DPR、持續負載下幀間隔 p95 ≤ 33.3 ms）定案；未通過的項目依第 3.4 節降級。

### 3.1 三個尺度

| 尺度 | 鏡頭高度（約） | 畫面內容 | 3D 單位 |
|---|---|---|---|
| 戰略（作戰室） | ≥ 2.6 km | 桌面＋整張紙圖＋棋子＋道具 | 不畫 |
| 作戰（地形） | 300 m–2.6 km | 紙色→地形、樹與房屋長出；棋子改為固定螢幕尺寸 | 不畫 |
| 戰術（近景） | < 300 m（離開門檻 380 m，避免來回抖動） | 寫實車輛、步兵、彈坑、煙；識別牌與地面識別環 | 畫（LOD0／LOD1） |

### 3.2 單位 LOD

| 層 | 何時用 | 三角形上限（提案） |
|---|---|---|
| LOD0 | 戰術尺度、距鏡頭 < 230 m、**位於視錐內**的車輛中，離鏡頭最近的前 12 台（距離相同取 `entityId` 小者；火砲與偵察車同樣占名額） | 每台 ≤ 30,000（真實車型的辨識特徵都在這層） |
| LOD1 | 230–1,600 m，或 LOD0 名額已滿 | 每台 ≤ 5,000（自動減化：去小零件、履帶改實心側板） |
| 棋子 | 作戰、戰略尺度 | 每塊 ≤ 500 |
| 步兵 | 所有 3D 尺度 | 每人 ≤ 400；一個小隊 8 人 |

- 同型車以 `InstancedMesh` 批次繪製：draw call 主要取決於入鏡的「車型 × 材質 × pass」，而不是單位數量。新增車型、材質、陰影與 AO pass 仍會增加 draw call。
- MVP 每個兵種只用 1–2 種車型，以控制批次數。
- LOD 驗收情境：單位全部聚集在一區、鏡頭快速橫移跨區、四兵種混編；每個情境下 LOD0 數量不超過 12，且被分到 LOD0 的確實是視錐內最近的車輛。

### 3.3 全場預算（提案）

| 項目 | 低畫質 | 高畫質 |
|---|---|---|
| DPR | 1 | min(裝置, 2) |
| draw calls／幀 | ≤ 150 | ≤ 450 |
| 三角形／幀（含所有 pass） | ≤ 60 萬 | ≤ 160 萬 |
| 陰影 | 無 shadow map；單位底下的 blob 陰影畫在地形 shader 內 | 1 張 2048² shadow map，範圍跟著鏡頭；地形只接收 |
| 後製 | 無 | 半解析度 AO；縮放過渡中暫停 |
| 不使用 | 即時景深、bloom、SSR、體積光、電影調色 | 同左 |

- **GPU 記憶體**：CP2 須提交預算表，每列記錄：項目（貼圖、shadow map、AO 法線／深度與中介目標、MSAA 合成目標、DPR 2 時的繪圖緩衝）、格式、尺寸、取樣數、估算大小，並標明「估算」或「實機量測」。實機比較方法：同一場景（正常 60 單位、戰術尺度）逐一關閉陰影、AO、MSAA、把 DPR 由 2 降到 1，各量一次幀間隔 p95，記錄每項的成本與降級效果。
- **首局下載**：以正式建置的全部必要網路資源驗收 ≤ 5 MiB。程式建模與程式產生貼圖讓下載很小，但成本轉到啟動時間；貼圖生成要移到 Worker 或改為建置時產生壓縮貼圖（KTX2），並量測 iPad 冷啟動到可互動的時間。

### 3.4 降級順序（實機未達標時）

1. AO 只在戰術尺度開 → 2. 拿掉 AO，改用頂點色縫隙暗化 → 3. 高畫質 DPR 降到 1.5 → 4. 縮小 shadow map 範圍或改回 blob 陰影 → 5. LOD0 名額由 12 降到 8。

### 3.5 製作流程

- **程式建模為主**：載具、道具、地形幾何由程式產生，依真實尺寸與照片規格建模；塗裝、迷彩與塵土由 shader 產生，因此可換陣營識別、不需要貼圖檔。
- **Blender 只做參考、量測、烘焙**：三視圖剪影比對、必要時烘 AO 或細節法線。不把高模匯出成執行期資產（檔案大、塗裝烘死、無法換色）。
- **例外**：不需換色、數量少、形狀有機的道具（例如作戰室的電話、檯燈）可用 glb，條件是 meshopt 壓縮、每件 ≤ 150 KB、合計 ≤ 1 MB，並記入 `ASSETS.md`。

## 4. 鏡頭與縮放

- 三個尺度連續縮放（第 3.1 節）；捏合與滾輪共用，以游標或兩指中點為錨點。
- 俯角隨縮放變化：戰略約 64°、作戰 64°→50°、戰術約 40–45°；不做自由旋轉。
- 棋子 ↔ 3D 單位的過渡約 300 ms：棋子收合、模型從地面長出；「減少動態」開啟時改為淡入淡出（與第 5 節一致）。選取狀態跨尺度保留。
- 未確認接觸只有「區」的精度：標記位置一律由 `PlayerView` 中該接觸的區域決定，不代表精確座標。區域在畫面內時畫在該區中心附近；區域不在畫面內時，畫在畫面邊緣、指向該區的方向。同一區有多個接觸（例如真實接觸群與假接觸並列）時，依 contact ID 固定順序橫向排開，不重疊。驗收：鏡頭跨區橫移時，每個標記始終對應正確的區域。

## 5. 動畫

| 類別 | 要點 |
|---|---|
| 指令回饋 | 下令後 100 ms 內有可見回饋（路徑線、棋子微跳、無線電確認音） |
| 移動 | 沿區域路徑平滑移動；裝甲有輕微懸吊晃動，步兵以小隊隊形移動 |
| 交戰 | 曳光、槍口火光、命中閃爍；HP 減少有清楚的數字或條狀變化 |
| 擊毀 | 煙霧＋單位傾倒／棋子翻面（「失能」，非血腥，依 content-policy） |
| 情報 | 接觸出現：雜訊閃爍淡入；掃描：雷達波掃過區域；誘餌識破：標記被擦掉 |
| 結算 | 時間軸回放關鍵情報與誘餌事件（CP3） |
| 減少動態 | 系統開啟「減少動態」時，縮放過渡改為淡入淡出、取消晃動與閃爍 |

## 6. 音效與音樂

- **情報事件有專屬聲音**：新接觸（短促雜訊＋電報音）、掃描（掃描嗶聲）、誘餌放置（無線電假訊號）、識破（訊號中斷）。玩家閉著眼也能知道發生了什麼。
- **無線電通話**：單位確認指令以短句或無語意的語音樣式呈現；首版不做多語配音。
- **音樂**：低張力底層＋接戰時加層的適應性配樂；暫停時壓低。
- **混音與可及性**：主音量、音效、音樂分開調整；所有重要音訊都有視覺對應（不只靠聲音傳遞資訊）。
- **iPad Safari 限制**：音訊需在使用者第一次點擊後解鎖；不依賴震動回饋（Safari 不支援）。

## 7. 介面

- 介面語言延續作戰室：紙張、打字機字樣的標籤、印章式按鈕；但可讀性優先，正文用清楚的無襯線字型。
- 觸控目標 ≥ 44 px；主要操作不依賴 hover、右鍵或鍵盤。
- 字型只用授權允許網頁嵌入且支援繁中的字型；記入 `ASSETS.md`。

## 8. 產出流程

1. **探索稿**：只供內部討論。第一輪（AI 生成、手繪微縮風格）已否決，改走寫實。
2. **目標畫面**：以 three.js 原型直接渲染（不使用 AI 生圖），截圖附 draw calls、三角形數與量測條件；實機重現前不公開。
3. **實機重現**（CP2）：在 M1 iPad Safari 以正常 60 可動單位量測，同時達到效能門檻並與目標畫面並排比對；通過後 DEC-07 定案。
4. **展示圖**（CP3 之後）：從標記版本的實機建置擷取。
