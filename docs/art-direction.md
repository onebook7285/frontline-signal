# 畫面、動畫與音效方向（Art, Motion & Audio Direction）

- 版本：v0.1｜2026-11-23｜狀態：提案，CP2 以目標畫面實機驗證後定案（DEC-07）
- 對應：REQ-10、REQ-11、H-06；效能門檻見 `docs/agent-plan.md` 第 04 節
- 原則：**好看要建立在跑得動上**。所有視覺決定都要能在 M1 iPad Safari、正常場景 60 單位、幀間隔 p95 ≤ 33.3 ms 下成立。

## 1. 展示即成品（Fidelity Rule）

對外看到的畫面，必須是玩家實際玩到的畫面。圖像分三級，只有第三級能對外使用：

| 等級 | 是什麼 | 怎麼產生 | 可以用在哪 |
|---|---|---|---|
| 探索稿 | 風格、色彩、氛圍的探索 | 手繪、AI 生成皆可 | 只供內部討論；**不放 README、商店頁、社群** |
| 目標畫面（Target Frame） | 某個場景「成品應該長這樣」的定稿 | 探索稿收斂後，附上**可重現性說明**（用了哪些幾何、材質、光照、特效，各自的效能成本） | 內部開發規格；**實機重現前不公開**。本文件只以文字描述目標畫面的規格 |
| 展示圖 | 對外宣傳、商店頁、README 截圖 | **只能**是遊戲建置在實機上的擷取；記錄 commit、裝置、畫質設定；不得後製修圖（裁切與縮放除外） | 任何地方 |

驗收方式：每張目標畫面都要在對應 checkpoint 以引擎實機重現，與目標畫面並排比對，並同時達到效能門檻。**重現不了的目標畫面要修改目標，不是修改截圖。**

## 2. 視覺支柱

1. **作戰室沙盤**：遠景是一張鋪在桌上的作戰地圖——紙質地形、上色的木製／金屬棋子、油性筆標記的情報。玩家是坐在桌前的指揮官。
2. **微縮模型的近景**：拉近時，棋子平滑過渡為低模、手繪質感的微縮單位；像一座可以操作的模型沙盤，而不是寫實戰場。
3. **情報是看得見的**：未確認接觸是油性筆畫的問號與雜訊閃爍；已確認是實心棋子；最後已知位置是逐漸褪色的鉛筆圈；誘餌被識破時標記被擦掉。情報狀態一眼可辨，不用讀文字。
4. **訊號感**：「Signal」貫穿介面與聲音——無線電、電報、打字機、雜訊，作為情報事件的回饋語言。
5. **可讀性優先於細節**：敵我以形狀＋顏色＋位置三重區分；色盲與灰階下仍可讀（見 `docs/content-policy.md` 第 6 節）。

## 3. 渲染方向（為效能而設計的風格）

| 項目 | 方向 | 為什麼 |
|---|---|---|
| 幾何 | 低模、平面著色或少量 facet；單位 ≤ 1.5k 三角形，同兵種 instancing | 60 單位＋場景在 iPad 上的繪製次數可控 |
| 材質 | 手繪貼圖＋烘焙 AO，共用 1–2 張 atlas | 少材質切換、少貼圖記憶體 |
| 光照 | 1 盞方向光＋半球環境光；陰影用單位底下的 blob shadow | 避開即時陰影貼圖成本，風格上也符合桌上模型 |
| 後製 | 低畫質：無；高畫質：僅 FXAA 與輕微暗角 | 不讓畫面依賴昂貴後製，低畫質仍是同一個風格 |
| 特效 | 精靈圖（sprite）槍口火光、煙、曳光；粒子數有上限 | 可預算、可批次 |
| 景深與傾斜位移 | **不使用即時景深**；微縮感來自配色、比例與構圖 | 即時 DOF 在 iPad 上太貴，也是最容易讓概念圖做不出來的效果 |
| 遠景 | 2D 棋子與地圖貼圖，停送 3D 單位繪製 | 符合 ADR-0001 的雙尺度設計 |

## 4. 鏡頭與縮放

- 兩個尺度：**戰略（遠景沙盤）**與**戰術（近景微縮）**，中間連續縮放；捏合縮放與滾輪共用。
- 棋子 ↔ 單位的過渡在 250–350 ms 內完成：棋子立起並長出模型，或反向收合；選取狀態跨尺度保留。
- 鏡頭角度：遠景接近俯視（約 70°），近景約 45°；不做自由旋轉（降低觸控誤操作，也減少需要美術覆蓋的角度）。

## 5. 動畫

| 類別 | 要點 |
|---|---|
| 指令回饋 | 下令後 100 ms 內有可見回饋（路徑線、棋子微跳、無線電確認音） |
| 移動 | 沿區域路徑平滑移動；裝甲有輕微懸吊晃動，步兵以小隊隊形移動 |
| 交戰 | 曳光、槍口火光、命中閃爍；HP 減少有清楚的數字或條狀變化 |
| 擊毀 | 煙霧＋單位傾倒／棋子翻面（「失能」，非血腥，依 content-policy） |
| 情報 | 接觸出現：雜訊閃爍淡入；掃描：雷達波掃過區域；誘餌識破：標記被擦掉 |
| 結算 | 時間軸回放關鍵情報與誘餌事件（CP3） |
| 減少動態 | 系統開啟「減少動態」時，縮放過渡改為淡入淡出、取消晃動與閃爍 |

## 6. 音效與音樂

- **情報事件有專屬聲音**：新接觸（短促雜訊＋電報音）、掃描（掃描嗶聲）、誘餌放置（無線電假訊號）、識破（訊號中斷）。玩家閉著眼也能知道發生了什麼。
- **無線電通話**：單位確認指令以短句或無語意的語音樣式呈現；首版不做多語配音。
- **音樂**：低張力底層＋接戰時加層的適應性配樂；暫停時壓低。
- **混音與可及性**：主音量、音效、音樂分開調整；所有重要音訊都有視覺對應（不只靠聲音傳遞資訊）。
- **iPad Safari 限制**：音訊需在使用者第一次點擊後解鎖；不依賴震動回饋（Safari 不支援）。

## 7. 介面

- 介面語言延續作戰室：紙張、打字機字樣的標籤、印章式按鈕；但可讀性優先，正文用清楚的無襯線字型。
- 觸控目標 ≥ 44 px；主要操作不依賴 hover、右鍵或鍵盤。
- 字型只用授權允許網頁嵌入且支援繁中的字型；記入 `ASSETS.md`。

## 8. 產出流程

1. **探索稿**（CP1 期間平行進行）：3 個方向 × 遠景／近景各 1 張，並附情報標記與 UI 的小樣。AI 生成的圖要記錄工具與條款，只供內部討論。
2. **目標畫面**（CP2 前）：收斂為 1 個方向，產出 2 張目標畫面（遠景沙盤、近景交戰）＋可重現性說明；圖像留在內部，本文件更新文字規格。
3. **實機重現**（CP2）：Three.js 切片在 M1 iPad Safari 重現兩張目標畫面，並排比對＋效能量測；通過後 DEC-07 定案。
4. **展示圖**（CP3 之後）：從標記版本的實機建置擷取。
