# 內容政策（Content Policy）

- 版本：v0.2.1｜2026-11-23（沿用 v0.2 草案；第 1 節「真實型號」一條為【暫定】，待 DEC-06 拍板）
- 適用範圍：遊戲內容、美術、音訊、文案、截圖、預告、商店頁、Roblox 版本、repo 內的範例與測試素材。
- 目的：讓二戰至戰後題材保持可讀、架空、可公開，不落入歷史宣傳、仇恨符號或平台審核風險。
- 原則：**可讀性與架空優先；不模擬真實暴行，不榮耀真實政權。**

## 1. 世界觀

- 使用**虛構陣營**、虛構國名、虛構徽章與虛構單位型號。
- 時代感來自輪廓、材質、顏色與科技水平，不來自真實國旗、黨徽、軍階、部隊番號或政治領袖。
- 【暫定，DEC-06】不使用真實坦克、飛機、船艦的型號名稱或性能數據；用「中型坦克」「偵察車」「火砲」等通用類別。
- 不重現真實戰役、屠殺、佔領、集中營、平民迫害或政治宣傳。
- 不把真實歷史團體映射成「好人／壞人」；陣營衝突是架空世界的戰爭，不是歷史判決。
- 若某個設計「看起來像真實陣營」，改形狀、改色塊、改徽章，不要只改名字。

## 2. 暴力與傷害

- 戰鬥是抽象的：車輛、砲塔、設施與幾何化的士兵單位；爆炸是色塊與粒子，不是血肉。
- 無血腥、斷肢、屍體堆疊、酷刑、性暴力、兒童兵或平民傷亡的描寫。
- 不把真實平民或受難群體當成遊戲目標或笑點。
- 單位被擊毀時，呈現「失去戰鬥能力」而非「死亡動畫」；文字用「擊毀」「失能」「退出戰鬥」。
- 不做逼真的傷亡統計或屠殺計數；擊毀統計是遊戲機制，不是歷史記帳。

## 3. 符號與政治

- 禁止納粹、法西斯、仇恨團體、極端政治組織的符號、旗幟、徽章、手勢、口號與變體。
- 禁止真實國旗、軍徽、政黨標誌、領導人肖像；避免「換色但輪廓相同」的擦邊設計。
- 禁止政治宣傳、種族歧視、性別歧視、宗教仇恨、排外與去人化語言。
- 若社群素材或貢獻帶有上述內容，維護者可移除，不另行辯論。
- 對歷史敏感議題：不調侃、不美化、不否認；必要時在文件中說明「本作是架空設定」。

## 4. 素材與授權

- 只使用**原創**、**明確授權**或**公共領域**的素材；不抓取遊戲、電影、模型網站或搜尋圖片的資產。
- 每個素材要記錄：路徑、作者、來源、授權、是否修改、署名方式。集中放在 [`ASSETS.md`](../ASSETS.md)。
- 字型、音效、音樂、圖示、紋理、筆刷都算素材；不要假設「網路上的免費字型」可商用。
- AI 輔助生成的素材要記錄工具、提示與使用條款；若授權不明，不用。
- 貢獻素材時，貢獻者要確認自己有權授權；不確定就先開 issue 討論。
- 截圖與預告片也要檢查：不能露出真實商標、私人資訊、未授權素材。

## 5. 平台與年齡

- Web 版沒有帳號與聊天；MVP 不做使用者生成內容。
- Roblox 版本若立案，依平台要求填內容問卷、年齡分級與受眾設定；不假設一定能上架或一定能給未滿 16 歲玩家。
- 首版 Roblox 不設自由文字、自製聊天或玩家上傳圖片；若未來加入，先寫審核與檢舉流程。
- 商店頁、縮圖、預告片也要遵守本政策；不能為了好點閱率使用擦邊歷史符號。
- 平台規則會變；每次決策前重新查證，不把舊規則當保證。

## 6. 可讀性與無障礙

- 敵我識別不能只靠顏色；形狀、輪廓、圖標、位置與動態都要有區分。
- 不做快速閃爍、強烈震動或可能誘發光敏感的效果；提供減少動態選項。
- 重要資訊（補給、佇列、總部生命、勝負）要有文字或圖標，不只靠顏色或音效。
- 音效若加入，提供靜音與音量；重要音訊要有視覺替代。
- 觸控目標足夠大；不要求精細拖拽或長時間按住。

## 7. 貢獻審查清單

PR 涉及內容時，逐項確認：

- [ ] 沒有真實國旗、軍徽、政黨標誌、仇恨符號或擦邊變體。
- [ ] 沒有真實裝備型號、性能數據或歷史戰役重現。
- [ ] 沒有血腥、斷肢、平民傷害、酷刑、性暴力或兒童兵。
- [ ] 沒有歧視、政治宣傳、去人化或調侃受難群體的文案。
- [ ] 素材來源、授權、作者與修改方式已記入 `ASSETS.md`。
- [ ] 截圖／預告沒有私人資訊、商標或未授權素材。
- [ ] 顏色不是唯一的識別方式；灰階與色盲模擬仍可讀。
- [ ] 沒有快速閃爍或光敏感風險。

## 8. 檢舉與處理

- repo 內的內容爭議：開 issue 或寄 GitHub Security Advisory（若涉及敏感或私人資訊）。
- 不要在新 issue 貼出可識別個資、仇恨內容原文或未授權素材。
- 維護者可以要求修改、移除或拒絕合併；重大爭議會記錄在 DEC／ADR，但不會公開私人資訊。
- 若平台（Roblox、商店、社群）要求下架或修改，先暫停該內容，再依平台流程處理。

## 9. 有疑問時

選**更抽象、更架空、更少歷史指涉**的版本。寧可少一分「真實感」，不要多一分審核與傷害風險。若不確定，先開 issue 問，不要先做再說。
